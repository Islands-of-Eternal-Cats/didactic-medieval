## Context

В `create_game_world` (`crates/core/src/world.rs`) юниты спавнятся с помощью `rng.gen_range(0.0..FIELD_WIDTH)` и `rng.gen_range(0.0..FIELD_HEIGHT)` — произвольные пиксельные координаты по всему полю. Тайловая карта (`TileMapResource`) генерируется из того же `seed`, но ~12% ячеек помечены как непроходимые. Система pathfinding (`find_path_action`) уже корректно выбирает только проходимые цели через `is_walkable`, но начальный спавн этой проверки не делает.

## Goals / Non-Goals

**Goals:**

- Все юниты при `createGameWorld` размещаются на проходимых тайлах.
- Детерминизм по `seed` сохраняется.
- Позиции — центры тайлов (как при pathfinding через `tile_to_world`), чтобы юнит однозначно лежал на одном тайле.

**Non-Goals:**

- Изменение логики ретаргетинга при движении (уже учитывает `is_walkable`).
- Разрешение коллизий «два юнита на одном тайле» при спавне.
- Изменение UI или формата WASM API.

## Decisions

### 1. Выбор тайла вместо произвольных координат

**Решение:** при спавне перебирать случайные `(col, row)` до нахождения проходимого тайла, затем ставить юнита в `tile_to_world(col, row)`.

**Альтернатива:** предварительно собрать список всех проходимых индексов и выбирать из него — проще гарантировать равномерность, но требует дополнительной аллокации при каждом `createGameWorld`. Для 475 тайлов и типичного `unitCount` (50) перебор по `is_walkable` достаточен и проще.

**Почему перебор:** минимальный diff, тот же паттерн что в `find_path_action` (`MAX_RETARGET_ATTEMPTS`), не меняет порядок потребления RNG критично при малом `unitCount`.

### 2. Порядок инициализации

**Решение:** сначала создать `TileMapResource::new(seed)`, затем спавнить юнитов с тем же `StdRng`, продолжая последовательность RNG после генерации карты (как сейчас — один `rng` на всё).

**Альтернатива:** отдельный RNG для спавна — сломает детерминизм относительно текущего поведения seed.

### 3. Размещение вспомогательной логики

**Решение:** добавить метод `TileMapResource::random_walkable_tile(&mut rng) -> (u32, u32)` в `resources.rs`, используемый из `world.rs`.

**Почему:** переиспользуемая логика рядом с `is_walkable` и `tile_to_world`; `world.rs` остаётся тонким.

### 4. Лимит попыток

**Решение:** использовать константу `MAX_SPAWN_ATTEMPTS` (например, 50) с fallback на первый проходимый тайл при исчерпании попыток.

**Почему:** при ~88% проходимых тайлов вероятность неудачи за 50 попыток пренебрежимо мала; fallback гарантирует отсутствие паники даже при экстремальных картах.

## Risks / Trade-offs

- **[Несколько юнитов на одном тайле]** → допустимо для текущего scope; коллизии не моделируются.
- **[Сдвиг детерминизма]** → позиции изменятся относительно текущего бага, но останутся детерминированными для фиксированного `seed`; это ожидаемо при исправлении.
- **[Расход RNG]** → незначителен при типичном `unitCount`.

## Migration Plan

Изменение только в WASM-модуле. После правки — `npm run build:wasm`. Откат: revert коммита. Миграция данных не нужна.
