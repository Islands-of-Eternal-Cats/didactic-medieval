## Why

Текущий рендер сцены (`src/UnitsCanvas.tsx`) использует Canvas 2D с ручным циклом `ctx.drawImage` для тайлмапа и 50 юнитов каждый кадр. Это упирается в CPU и ограничивает выразительность графики: нет Y-sort (юниты перекрывают друг друга в неправильном порядке), нет теней, нет направлений юнитов, autotiling недоступен, синхронная фаза анимации делает марш «как на параде». Чтобы поднять визуальную читаемость (кто куда идёт, кто перед кем, где препятствие) и оставить запас по производительности на сотни юнитов, нужно перейти на WebGL-рендер с правильной структурой сцены.

## What Changes

- **BREAKING**: Замена Canvas 2D рендерера на PixiJS v8 (WebGL2). Внутреннее API игрового ядра (`getTileMap`, `getUnitPositions`, `tick`) не меняется.
- Логический тайл рендера увеличивается с 16 px до 32 px; сцена 800×608 (было 400×304 CSS-масштаб ×2).
- Новая структура слоёв сцены: `terrain` → `decals` (тени) → `units` (с Y-sort) → `overlay`.
- Юниты получают тени, направление движения (N/S/E/W) и асинхронную фазу анимации шагов.
- Тайлмап получает autotiling переходов трава↔вода и трава↔камень и декор на проходимых клетках (цветы/мелочи).
- Процедурные спрайты рыцарей расширяются: 4 направления и шейдинг; источник остаётся в `src/pixelSprites.ts`.
- Добавляется зависимость `pixi.js@^8`.
- Rust/WASM ядро (`crates/core/**`) не трогается.

## Capabilities

### New Capabilities
- `pixi-scene-renderer`: WebGL-рендерер сцены на PixiJS с многослойной структурой (`terrain`, `decals`, `units`, `overlay`), управлением жизненным циклом `Application` и интеграцией в React.
- `unit-sprite-rendering`: визуальное представление юнитов как Pixi-спрайтов с тенью, Y-sort по координате Y, определением направления движения, асинхронной фазой шагов и кэшем текстур.
- `tile-autotiling`: подбор переходных тайлов по 4-соседской bitmask для границ трава↔вода и трава↔камень, плюс декоративные объекты на проходимых клетках.

### Modified Capabilities
- `pixel-art-units`: требования рендера юнитов мигрируют с Canvas 2D на Pixi-спрайты; добавляются 4 направления и асинхронная анимация.
- `tile-map-rendering`: требования рендера тайлмапа мигрируют с Canvas 2D на Pixi `Container` + `Sprite`; добавляется autotiling и декор.

## Impact

- **Код фронтенда**: переписываются `src/UnitsCanvas.tsx`, `src/tileMapRenderer.ts`, `src/pixelSprites.ts`; добавляется директория `src/render/` (SceneRenderer, textures, terrain, UnitSprite, autotile).
- **Зависимости**: добавляется `pixi.js@^8`. Размер бандла растёт (≈+650 KB до gzip, ≈+160 KB после).
- **Сборка**: `npm run build` сохраняет тот же сценарий; никаких изменений в Vite/wasm-pack.
- **Производительность**: рендер 525+ спрайтов сводится к 1–3 draw call (батчинг по общему `BaseTexture` тайлсета и кэшу текстур юнитов). Освобождается CPU.
- **API WASM ↔ фронт**: без изменений (`createGameWorld`, `getTileMap`, `getUnitPositions`, `tick`).
- **Тесты**: новых автоматических тестов не вводится в этом change; верификация — визуальная (через `chrome-devtools` MCP, скриншоты и проверки DOM/WebGL).
- **Riски**: совместимость WebGL2 (минимум — все современные браузеры); пиксель-арт остаётся чётким благодаря `scaleMode: 'nearest'` и `roundPixels`.
